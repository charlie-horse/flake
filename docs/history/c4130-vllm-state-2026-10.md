## Pre-cutover stack (the fork, github.com/charlie-horse/vLLM)
- `flake.nix` exported `packages.x86_64-linux.vllm` (= `default`, the wrapped sm_70 build) and `nixosModules.vllm` (= `default`, imports `lmcache`) + `nixosModules.lmcache`. Files: `nix/module.nix` (vllm service, built-in models), `nix/lmcache.nix` (server, dashboard, L2 pruner), `nix/packages-module.nix` (package set built once with the host's `pkgs`), `nix/package.nix` (env + wrappers; returns `{ vllm, vllmFlint, lmcacheUi, flintConverter, flintCheckpoint, ... }`), `nix/flint.nix` (sm_70 tree, converter, checkpoint), `nix/source.nix` (serving tree = repo minus `nix/`, `flake.*`), `nix/pyenv/`, `nix/README.md`.
- nixpkgs was shared with the host via `follows` (vllm-sm70 has no follows). pyproject-nix, uv2nix and build-system-pkgs were pinned by the fork's own lock.
- The old option names `c4130.vllm.activeModel` / `c4130.vllm.kvTiers.*` were renamed aliases (with a warning).
- Python env (`nix/pyenv/pyproject.toml` + `uv.lock`, via uv2nix): 1Cat-vLLM 1.5.1 (Volta fork of vLLM) from its SM70 release wheel; torch 2.10.0+cu128; LMCache 0.5.6 from its PyPI sdist with `LMCACHE_CUDA_MAJOR=12` (deps declared in `[[tool.uv.dependency-metadata]]`, numpy/prometheus/otel bounds relaxed; `no-binary-package = ["lmcache"]` + `sourcePreference = "sdist"`; `grpcio-tools` in the build-only `lmcache-build` group; built against torch 2.10, not the `torch==2.13` LMCache's build-system pins). Re-lock: `uv lock --python 3.12` in `nix/pyenv` (uv isn't on c4130).
- Wrappers set `LD_LIBRARY_PATH` (driver libs, nvidia-* wheel libs, `tvm_ffi`, `z3`), `CUDA_HOME` = CUDA 12.8 and `NVCC_PREPEND_FLAGS=-I<toolkit>/include` for the JIT.
- 1Cat's bundled LMCache connector targeted an older API (`lmcache.v1.multiprocess.mq`/`protocol` gone), hence `kv_connector_module_path`. At fork `5fc02fa` the factory (`vllm/distributed/kv_transfer/kv_connector/factory.py:105-107`) imported the module path before its registry (`:124`); its HMA check (`:54-60`) passed because `LMCacheMPConnector` declares `SupportsHMA`.
- **Flint** ran on the fork's source tree (`vllmFlint`: the stock venv with the fork tree first on `PYTHONPATH`, store name `1cat-vllm-flint-1.5.1.dev0+flint`); the Qwen entries used the 1.5.1 wheel. A tree rebuild took ~35 min at MAX_JOBS 16; commits touching only `nix/` or `flake.*` didn't rebuild it. The `sm70_flash_attn_*` patch list in `nix/flint.nix` had to match the fork's `vllm_flash_attn.cmake` (CMake skips them when `VLLM_FLASH_ATTN_SRC_DIR` is set). Flags then: `--kernel-config.sm70_skinny_moe false`, the plain glm47 reasoning parser (reasoning in `reasoning_content`). Kernel switches fell back to TurboMind.
- Before fork `647bceb` the checkpoint was input-addressed and moved with the env (`v3798n9…`, `9rw8az0d…`, same content). The converted output is byte-identical to the former hand-converted `~/flint/models/flint-nvfp4-modelopt`.

## State as of 2026-10-29
- Flint live on `vllm.service` (2026-10-30 00:45 EDT) with LMCache on (L1 64 GB, L2 180 GB), fork `2eb8f3b` (main, with the GPU decode fusions; converter `f66728d`).
  - Nix-built service, 4K single stream: 173.8 tok/s default / 175.8 greedy, ITL 5.62 ms, TTFT 0.70 s; the dev tree measured 179.3 / 179.5 at ITL 5.59 ms (run spread). Previous pin `5fc02fa`: 117.8 / 123.0.
  - LMCache verified: a fixed 8K prompt re-sent after a vllm-only restart (L1 warm) took 0.31 s (later 0.27 s) vs 1.56 s (1.59 s) cold, identical output; 36 GB of L2 after a few 4K requests.
  - New default-on kill switches then: `VLLM_SM70_FLINT_FUSED_ROUTER`, `_ATTN_FUSED_DECODE`, `_QK_ROPE_KV`, `_SAMPLER`, `_AR_RMSNORM`; `VLLM_SM70_FLINT_MOE_PERSISTENT` off by default.
  - Smoke test passed (17×23 → 391). The hand-run `~/flint/serve.sh`, `convert.sh`, `dl.sh` were retired (copies in `~admin/archive/notes/flint-nix/retired/`); `~/flint` was later deleted.
- What went wrong on the way (all fixed in config):
  - The first switch (12:53) ran the box out of RAM: 96 GB L1 plus Flint's ~27 GB load peak, no swap. The page cache starved, startup crawled for 14 min, SSH and ping stopped until the OOM killer hit LMCache at 13:06. Qwen had left only ~16–18 GB free. L1 default became 64 GB.
  - The second start restart-looped on the expandable-segments IPC issue (see [Flint serving profile](../hosts/c4130-vllm.md#serving-profile)).
  - Step backups in `~admin/archive/notes/flint-nix/`: `default.nix.pre-l1-64`, `default.nix.pre-noexpand`, `CLAUDE.md.pre-l1-64`, `SWITCH-STEPS.md`, switch logs.
- Before Flint the default model was `qwen3.8-27b`. Qwen3.8-27B (FP8 + DFlash2, 150K context, 0.91 utilization, chunk size 8192) was verified with LMCache at L1 96 GB: cold 100K-token prompt 66 s TTFT, from L1 1.8 s, from L2 9.1 s, identical answers; 4K decode ~80–128 tok/s. At 64 GB L1, re-check hits before relying on it. Qwen3.6's `lmcacheChunkSize = 1056` was never verified (its test didn't finish).
- **Dashboard** (`vllm-lmcache-ui`) under systemd since the 13:33 switch: `/` 200, `/api/nodes` lists the server; figures under real traffic and the units running as `vllm` with `StateDirectory` were not checked yet. Validated out of band first: `nix eval` of the `ExecStart`s and `nix build --no-link` of the toplevel; a standalone pair as charlie (`lmcache server … --port 5556 --http-port 8086 --chunk-size 256 --l1-size-gb 2`, 2 GB L2 under `~/lmcache-uitest`, dashboard on 127.0.0.1:8087): clean start, ~3.5 GB RSS, 316 MiB on one GPU, all routes 200, unregistered proxy target 403. All of it, and the temporary `tailscale serve --http=8081` bridge, was removed.
- Bridging the dashboard before a switch: `sudo tailscale serve --bg --http=8081 http://127.0.0.1:<port>` (matches on the Host header, so use `http://c4130:8081/`); persistent root state outside Nix, undo with `sudo tailscale serve --http=8081 off` before the real unit claims 8081.
