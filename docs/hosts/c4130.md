# c4130: GPU inference host

c4130 is one of the three NixOS 26.05 servers (c4130, r440, m2mini) that run the cluster. Besides its etcd member, control plane and kubelet ([cluster runbook](../cluster.md)), it runs vLLM and LMCache on two V100s ([c4130-vllm.md](c4130-vllm.md)).

Config: `hosts/c4130/`, built through `lib.system.x86_64-linux.mkServer` (`parts/hosts.nix`, `lib/system/mkServer.nix`), so it gets only its host dir plus `modules/cluster` and `modules/server`.

| File | What it holds |
|---|---|
| `hosts/c4130/default.nix` | import list (order matters for byte-identical output; keep it) |
| `hosts/c4130/configuration.nix` | base system, firewall, Tailscale prefs, md RAID event logging, `legacyCharlie` switch |
| `hosts/c4130/hardware-configuration.nix` | RAID, filesystems, NVIDIA driver, container toolkit |
| `hosts/c4130/vllm/default.nix` | host values for the vLLM / LMCache modules from input `vllm-fork` ([c4130-vllm.md](c4130-vllm.md)) |
| `hosts/c4130/builder.nix` | remote builds on r440 over bond0 ([build-cache.md](../build-cache.md)) |

## Hardware
- 2× Tesla V100-PCIe-32GB, both sm_70, on the same PCIe switch with no NVLink. NVIDIA datacenter driver (`hardware.nvidia.datacenter.enable`, proprietary module, `open = false`; fabricmanager forced off, no NVSwitch). Check the driver branch with `nvidia-smi`; it must be one that still supports Volta (580).
- 48 threads, 125 GB RAM, no swap (`swapDevices = [ ]`).
- Root: ext4 `C4130-ROOT` on SATA SSD md RAID1 (`/dev/md/local_store`). There is no MTA, so md events (Fail, DegradedArray, …) go to the journal: `journalctl -t mdadm`.
- In Kubernetes the node is tainted `nvidia.com/gpu=vllm:NoSchedule` and labelled `nvidia.com/gpu.present=true`; only workloads that tolerate the taint (one-per-node ones) land there. The GPUs belong to `vllm.service` ([c4130-vllm.md](c4130-vllm.md#vllmservice-owns-the-gpus)).

### CUDA and Volta constraints
- **CUDA 13 can't target sm_70.** Anything that compiles or ships GPU kernels must use CUDA 12.x (vllm-sm70 pins its CUDA and torch versions in its own repo).
- No bf16 on Volta: run everything as `--dtype half` (the vLLM module adds it for every model).
- PyPI ships only CUDA 13 LMCache wheels, so LMCache is built from source against CUDA 12 ([c4130-vllm.md](c4130-vllm.md#lmcache)).

## Network
- LAN `eno1` at `10.0.0.95`; Tailscale advertises exit node + `10.0.1.0/24`, tag `tag:node` (`server.tailscale`, `modules/server/tailscale.nix`).
- Open globally: TCP 22, 80, 443. Cluster ports are opened by `modules/cluster` to the cluster nodes only.
- vLLM API 8000 on `eno1` + `tailscale0`, and on `bond0` from r440 (`10.25.0.2`) only (`builder.nix`). LMCache dashboard 8081 on `eno1` + `tailscale0`. Neither has authentication; access is limited by network only.
- Direct 2×25G link to r440: LACP `bond0`, c4130 `10.25.0.1/30` (details: [build-cache.md](../build-cache.md)).

## Deploying c4130
Every change, including a model entry or a `vllm-fork` re-lock, goes through this repo: branch, CI, merge (general rules: [cluster runbook](../cluster.md#changing-a-host)). Then, as admin on c4130:

```sh
# 1. GC first
sudo nix-env -p /nix/var/nix/profiles/system --delete-generations +2 && sudo nix-collect-garbage
df -h /
# 2. pull and build (no sudo; the build itself runs on r440)
cd /etc/nixos && git pull && nixos-rebuild build --flake /etc/nixos#c4130
# 3. optional, around risky starts: the RAM guard (see below)
# 4. switch
sudo nixos-rebuild switch --flake /etc/nixos#c4130
```

- **GC before every switch.** After a switch that replaces the Flint checkpoint, also GC the old ~23 GB checkpoint path.
- `switch` exiting with status 4 means a unit failed: read `systemctl --failed`. etcd runs here too: switch one host at a time and run the etcd health check from the [cluster runbook](../cluster.md#changing-a-host) afterwards.
- Never run `nix flake update` or edit files in `/etc/nixos` on the host.
- What c4130 runs: `nix-store -qd /run/current-system` and `git -C /etc/nixos log -1`. The deployed `vllm-fork` commit is the one in `flake.lock` at that commit; `main` may be ahead.
- Watch a vLLM start with `journalctl _SYSTEMD_INVOCATION_ID=$(systemctl show -p InvocationID --value vllm)` (3–6 min; the first start of a new model also JIT-compiles kernels). Look for "Application startup complete" or a Traceback.
- **RAM guard.** `~admin/archive/notes/flint-nix/ramguard.sh` stops vllm and LMCache if MemAvailable drops under 6 GB (runs ~25 min): `sudo systemd-run --unit=ramguard --collect ~admin/archive/notes/flint-nix/ramguard.sh`. Use it around risky starts (new model, bigger L1, `vllm-fork` bump).

### Builds
c4130 builds nothing itself (`nix.settings.max-jobs = 0`): every derivation goes to r440, and substitutes come from `https://cache.neuros.is`. Builder, cache, concurrency limits and the bond0 link: [build-cache.md](../build-cache.md).

If r440 is down, build locally with `--option max-jobs 4`, and **stop LMCache first**: with a model and LMCache running only ~16–18 GB of RAM is free, while the Flint checkpoint conversion peaks at ~25 GB and a CUDA tree runs 16 nvcc jobs.

## Operational gotchas
- **pgrep over SSH.** `pgrep -f <pattern>` matches its own `bash -c` command line; use `ps -ef | grep '[x]yz'`.
- **Stopping vllm.** `Restart=on-failure` brings it back after a kill: `sudo systemctl kill --signal=SIGKILL vllm && sudo systemctl stop vllm`.
- **`nixos-rebuild build` writes `./result`**; use `nix build --no-link` when you only need to know it builds and don't want to clobber `~/result`.
