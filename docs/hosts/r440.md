# r440

Dell PowerEdge R440, x86_64, NixOS 26.05. Config: `hosts/r440/`. One of the
three cluster nodes (etcd, control plane, worker; keepalived priority 100,
see [cluster.md](../cluster.md)), the Nix remote builder for c4130 and the
binary cache `https://cache.neuros.is` (both in
[build-cache.md](../build-cache.md)).

## How it is built

`parts/hosts.nix` builds r440 with `lib.system.x86_64-linux.mkServer`
(`lib/system/mkServer.nix`): the host dir + `modules/cluster` +
`modules/server`, on the flake's `nixpkgs` input (nixos-26.05, rev pinned in
`flake.lock`). It must not go through `mkHost`, which imports every
`modules/**` file (desktop, home-manager). Deploy: [cluster.md, Changing a
host](../cluster.md#changing-a-host).

r440 was ported from its standalone flake (`/etc/nixos`, via
`~/flint-nix/builder/etc-nixos`) in 2026-10
([history/cluster-handoff-2026-10.md](../history/cluster-handoff-2026-10.md)).
Its old `k8s.nix` (etcd, apiserver, controller-manager, scheduler, cri-o,
certs as Nix paths, a clusterCidr bug) was not ported: the shared cluster
module (`modules/cluster` + `cluster/definition.nix`) replaces it, including
the cluster-port firewall rules. The port kept the old module order to prove
a byte-identical toplevel; that was a one-time check, and `cache.nix`,
`containers.nix` and `memory.nix` have changed the output since, so the
import order no longer matters.

## Memory

r440 runs etcd, the control plane and kubelet next to c4130's remote builds,
with ~46 GiB of RAM and no disk swap. On 2026-11-04 two CUDA trees (2 jobs ×
16 nvcc) exhausted RAM: kswapd stalled, journald's watchdog fired and the box
hung. `memory.nix` adds three layers:

1. **zram swap** (zstd, 25% of RAM ≈ 11.5 GiB of swap, priority 100), so
   short spikes compress instead of stalling. At ~3:1 on anonymous pages it
   costs at most ~4 GiB of real RAM when full.
2. **A hard cap on `nix-daemon.service`**: `MemoryHigh=32G`,
   `MemoryMax=36G`, `MemorySwapMax=4G`. Every build runs in this cgroup,
   c4130's too (nixremote's `nix-daemon --stdio` forwards to the system
   daemon). MemoryHigh throttles and reclaims first; MemoryMax OOM-kills
   inside the cgroup (the largest process, i.e. an nvcc/cicc, failing that
   build). 46 − 36 leaves ~10 GiB for etcd, the control plane, kubelet and
   pods, harmonia and the kernel. MemorySwapMax keeps builds from slipping
   past the cap through zram (zram pages are not charged to the cgroup).
3. **OOM order**: `OOMScoreAdjust=500` on nix-daemon (builds inherit it), so
   if the box still runs out globally the kernel kills a build before etcd
   or kube-apiserver (0) or the kubelet (−999, set by itself).

The build concurrency itself (2 jobs × 8 cores) is sized in `builder.nix`
([build-cache.md](../build-cache.md)).

**kubelet and swap.** kubelet refuses to start with swap on unless
`failSwapOn = false` (the NixOS kubelet module doesn't handle swap).
`memorySwap.swapBehavior = "NoSwap"`: pods never swap (their cgroups get
`memory.swap.max = 0`); system daemons (etcd, apiserver, builds) may. This
is merged with the per-node `kubeletConfig` from `cluster/definition.nix`
(r440 has none). Don't drop it while zram is on, and `swapoff` before rolling
back to a generation without it.

## Containers

`virtualisation.containers.enable = true` keeps
`/etc/containers/{containers.conf,storage.conf,policy.json,registries.conf}`
exactly as they were under cri-o, which enabled it implicitly. The cri-o →
containerd swap must not change what rootless podman sees: charlie's
rootless podman (`--root` under `~/flint-swebench` and
`~/.local/share/containers`) used it.

After stage 2 of charlie's removal charlie's subuid range (100000:65536, in
`/var/lib/nixos/auto-subuid-map`) stays reserved and admin has its own, so
charlie's rootless container storage (`~/flint-swebench`, 68 GB) is not
usable by admin as is
([history/charlie-removal-2026-11.md](../history/charlie-removal-2026-11.md)).

## Firewall

iptables backend, ping allowed, as on c4130.

- **ssh (22)** on every interface (`configuration.nix`).
- **UDP 41641**, tailscaled's WireGuard port, for direct (non-relayed)
  connections.
- **`bond0`**: tcp 22 only, for c4130's remote builds. The cache is no longer
  served on the link; its nginx port (5080) is opened per source in
  `cache.nix` ([build-cache.md](../build-cache.md)).
- **`tailscale0`** is trusted on every node by `modules/cluster/firewall.nix`
  (admins and the cluster nodes, whose names resolve to 100.x via MagicDNS).
- **Cluster ports** (etcd 2379/2380, apiserver 6443, kubelet, flannel) are
  owned by `modules/cluster`, restricted to the cluster peers. Until 2026-10
  they lived in the host firewall (git history: `legacy-k8s-firewall.nix`).
